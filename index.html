01 / Selected work

Automation that runs in the real world

Five projects across manufacturing, machine safety and laboratory automation. Each one shows the problem, what was done and what changed as a result.

01Jun 2023 to Jan 2025
In daily useManufacturingIndustrial IoT

Condition monitoring automation for wood panel manufacturing

Role
Programme lead and budget holder
Tools
AVEVA Insight, Schneider TM262 with TM3, OPC-UA, Modbus, MQTT, Power BI

At a wood-based panel board plant in Scotland, I led an anomaly based condition monitoring programme across five production areas, and held its budget. An FMECA of 251 plant assets, ranked across five criticality levels, set the scope.

The hardware covered Schneider TM262 PLCs and a wireless sensor network. Plant data came in over OPC-UA, Modbus and MQTT, into a data historian with Power BI reporting. All installation ran under permit-to-work in ATEX zones, with risk assessments and method statements I wrote.

The system gave early warning of a bearing problem on the thermal oil system that the existing SCADA did not show. It moved from pilot stage to day-to-day use by process, production and maintenance engineers. Alongside it, I developed telematics based predictive maintenance and mapped AGV options for warehouse automation.

Why it mattersOn a continuous production line, a fault caught early is a planned repair instead of an unplanned stop.

02May 2026 to present
Certification in progressMachine safety

Machine safety testing and CE certification of a Cartesian robot

Standards
EN ISO 12100, Machinery Directive, CE marking
Outputs
Test plan, test records, NCRs, component compliance tracker

Preparing a three axis Cartesian robot for third party safety certification with Eurofins is my responsibility. I wrote the mechanical safety test plan of 32 tests and directed the testing.

One test showed that any magnet could defeat the guard interlock, a critical safety risk. Use of the machine was restricted straight away and a non-conformance raised. On my instruction, the design engineer redesigned it around a SICK reed switch. The NCR closed only after a verified re-test.

For each critical component, I gather compliance certificates from manufacturers and suppliers and track them against the certification evidence.

Why it mattersPeople work beside this machine every day, and a guard that anyone can bypass puts them at risk.

032025 to present
CompleteSDK ongoingOpen source

Python integration for automated instruments

Role
Proposed the approach to the R&D Director, then built it
Tools
Python, PyLabRobot, serial protocol capture, legacy instrument runtime

PyLabRobot is an open source Python framework for automating laboratory hardware. It lets users drive equipment from different makers in one Python workflow.

The first target was an automated liquid dispenser, a legacy serial device documented only by an old manual. Capturing its live serial traffic exposed the timing problems behind lost commands. It now runs from Python as a tested driver, fully compatible with PyLabRobot.

Building on that, I am leading a Python SDK for our robots. It sits on top of the existing control software through a defined interface, so proven code already serving customers stays unchanged.

Why it mattersPython support lets customers fit an instrument into their own automated workflows, next to the rest of their equipment.

04Feb to May 2026
Commissioned 22 Apr 2026Process automation

Replacing a decades old MS-DOS system with modern automation

Role
Requirements, protocols, testing, on-site commissioning, training

A biopharma lab in London was still running its gel punching process on an MS-DOS system. Working with the customer, I defined their requirements and wrote the protocols for the new automated system.

Tests of parallel and series vacuum set-ups showed which gave the better performance. I then commissioned the system on site and trained the customer's staff.

Since October 2025 I have also built and supported an automated column purification application for an OEM partner. To deliver these applications, I learned a proprietary robot programming language within two months.

ResultA faster Windows based system with run logging, on supported hardware the customer can maintain.

052019 to present
EmbeddedMotion controlDiagnostics

Embedded hardware, motion control and field commissioning

Parts and methods
Allegro A9102, RC filter design, MCU boards, LUT stepper control, protocol and log analysis

For a cover sensor, I designed a circuit around an Allegro A9102 linear Hall effect sensor. Parts of the original schematic were distorting the analog signal, so I removed them and added an RC low-pass filter to cut ADC noise.

Stepper motor motion profiles for the X, Y and Z axes came from the controller's speed lookup table. When a robot showed intermittent faults, its runtime logs pointed to a wireless link with an accessory module. Barcode read failures traced back to label print quality, fixed by changing the printer settings.

Field work includes a full service manual written from scratch, and commissioning at UKHSA Colindale and a biopharma site. Earlier, at Entrench Electronics, I designed microcontroller boards and built automation systems for university and industry labs.

Dissertation

Autonomous ground vehicle for warehouses and deliveries

Warehouses often have no GPS, so the robot builds a 2D map and localises itself in it. Odometry and IMU data are fused with an extended Kalman filter for its state estimate. I simulated it in ROS with Gazebo, gave it vision based navigation from an onboard camera, and built an Arduino prototype controlled over Bluetooth.
